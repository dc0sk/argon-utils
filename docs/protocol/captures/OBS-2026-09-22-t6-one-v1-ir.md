# OBS-2026-09-22-t6-one-v1-ir

Task T6, on an **Argon ONE V1** with a Raspberry Pi 4. **IR is wired to BCM 23 and works: the
Argon remote speaks NEC at address `0x00`, and ten distinct commands were read cleanly.**

Full output: [`t6-2026-09-22-one-v1-ir.log`](t6-2026-09-22-one-v1-ir.log).

## Method

`sudo dtoverlay gpio-ir gpio_pin=23` at runtime -- nothing written to `config.txt` -- which bound
GPIO23 as an `rc-core` receiver (`/dev/lirc0`, `rc2`, consumer `ir-receiver@17`). Then
`ir-ctl -r -d /dev/lirc0` for 90 s while the operator pressed several buttons on the Argon
remote. Raw capture only: no keymap was loaded and no scancode decoding was relied on.

The same overlay, tool, remote and operator had produced **nothing** on the ONE V5 two days
earlier (T6's first half), across four windows and every free GPIO line.

## Result

The waveform is textbook NEC: a 9 ms mark and 4.5 ms space, 32 bits of 560 us marks separated
by ~560 us (`0`) or ~1690 us (`1`) spaces, and 9 ms + 2.25 ms repeat frames while a key is held.

30 complete frames decoded, LSB first, every one passing both inverse checks:

| Address | Command | Times seen |
|---|---|---|
| `0x00` | `0x80` | 3 |
| `0x00` | `0x81` | 3 |
| `0x00` | `0x90` | 3 |
| `0x00` | `0x99` | 3 |
| `0x00` | `0x9c` | 3 |
| `0x00` | `0x9d` | 3 |
| `0x00` | `0xc1` | 3 |
| `0x00` | `0xca` | 3 |
| `0x00` | `0xcb` | 3 |
| `0x00` | `0xd2` | 3 |

The lines that did not decode are the repeat frames and lone edges between presses, which is
what they should be.

## What follows

- **`ONE-V1-IR-BCM23`: the receiver is on BCM 23**, as the pin assignment said, and it works
  with the stock `gpio-ir` overlay. No vendor software is involved.
- **`ONE-V1-IR-NEC`: the remote is NEC, address `0x00`.** Ten commands are recorded above.
- **The V5's silence was the board.** One case answers and the other never did, with everything
  else held constant -- so the V5 is simply not wired for IR, rather than the remote being dead
  or the method wrong. That closes the question this task opened.

## Not established

**Which button is which.** The operator pressed "several buttons" without recording the order,
so these ten codes are unlabelled. A keymap needs a second pass, one named button at a time --
and it must be built that way rather than copied: the vendor's own table is all-rights-reserved
and known to be wrong (a missing comma concatenates two names, leaving 10 names for 11 codes).

Whether the V2 or V3 use the same codes. Different cases, unmeasured.
